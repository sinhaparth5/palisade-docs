A single-binary **Web Application Firewall + reverse proxy** for Linux, built in Go on top of
[Coraza v3](https://github.com/corazawaf/coraza) (OWASP Core Rule Set) with a built-in
HTMX/Tailwind admin dashboard. There is **no Docker, database-server, or Node.js requirement**:
SQLite is the default, while MySQL/MariaDB and Postgres-compatible databases are available for
deployments that need an external store.

:::note[About the name]
The project was called **Coraza WAF Mod** (`coraza-waf-mod`) until v2.5.0. The binary, systemd
unit, service user, paths and metrics now all use `palisade`, and the GitHub repository is
[`sinhaparth5/palisade-waf`](https://github.com/sinhaparth5/palisade-waf). Upgrading an old install?
See [Migrating from coraza-waf-mod](/docs/installation/migrating-to-palisade). Palisade is
independent and is not affiliated with or endorsed by OWASP or the Coraza project.
:::

## What it does

Palisade sits in front of one or more backend web applications and inspects every incoming
HTTP request before it is allowed to reach a backend. For each request it runs an ordered
pipeline of defensive checks — IP blocklist, geo blocking, bot challenge, rate limiting, maintenance
and waiting-room gates, and full WAF rule inspection — and only then reverse-proxies the request to the matching backend. Every
decision (blocked or allowed) is logged asynchronously to the configured database. Most policy and
routing changes are managed live from the built-in dashboard; startup concerns such as the database
connection remain CLI-controlled.

It is designed to be **operationally boring**: a single statically-linked binary, SQLite by default,
a systemd unit, and an optional prune timer. Services, rules, TLS, bot settings, and rate limits are
configured through the dashboard and stored in the database. The database backend itself is a
startup choice and requires a restart to change.
